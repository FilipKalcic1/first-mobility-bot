## What changed (architecture)

**Deleted (5000+ LOC):**
- `services/v3_routing/` (entire experiment, never deployed)
- `services/v2/recognition.py` (anchor + LLM judge — replaced)
- `services/v2/domain_picker.py`, `domain_scoped_picker.py`
- `services/v2/hierarchical_entity_retrieval.py`, `confusion_disambiguator.py`
- `services/v2/query_normalizer.py`, `reference_resolver.py`
- V2_USE_TOOL_USE / V2_USE_UNIFIED_RESPONDER / V2_USE_V3_ROUTER branches in engine.py
- 5 dormant `scripts/phase_*` bench files + `auto_enrich_tkb.py`
- 17 dormant docs (PHASE_*, HONEST_*, HANDOFF*, REWRITE_SPEC*, etc.)
- 7 orphaned tests + entire `tests/v3_routing/` tree

**Added (~2100 LOC):**
- `services/router/anchor_index.py` — embed-once cosine index, max-over-phrases scoring
- `services/router/tool_schema_builder.py` — registry → OpenAI `tools=[]` schemas (handles 3 oversized tool names via stable hash aliases)
- `services/router/llm_router.py` — anchor top-50 → gpt-4o-mini `tool_choice="auto"` → `RouterResult{tool_id, params, confidence, alternatives, ...}`. Retry-with-backoff on 429.
- `services/formatter/llm_formatter.py` — backend JSON → Croatian text (reuses `services/v2/output_sanitizer` for prompt-injection defense and `services/v2/pii_scrubber` for output PII).

**Regenerated data:**
- `config/tool_anchor_enrichments.json` — 950 tools × 12 Croatian anchor phrases (gpt-4o-mini, realistic colloquial phrasing).
- `config/tool_knowledge_base.json` — 950 × 5 realistic Croatian example queries (preserved `intent_summary`, `use_when`, `do_not_use_when`, etc.).

**Engine wiring (`services/v2/engine.py`):**
- L-1 rate limit → L0.5 PII → L0.6 sanitizer → L0 identity → L1 special → L2 quick-path → L2a/L2b → **L3 LLMRouter** → L5 confidence_gate (via shim) → L6 mutation_gate → L7 executor → **L8 LLMFormatter**.
- Kept: quick-path, basics anchor, flow engine, mutation gate, pending clarify/mutation, conversation history, identity, rate limiter, PII, sanitizer, executor + api_gateway (OAuth, circuit breaker, tenant headers).

## Cost & latency

- Cost per query: ~$0.005 (anchor embed ~$0.0001 + router LLM ~$0.003 + formatter LLM ~$0.0005). At 1000 queries/day → ~$5/day.
- Latency: TKB-sweep measured p50 **2.9s**, p95 **11.5s**. The p95 is inflated by 429-retry backoffs (Azure dev quota); production traffic at 1-5 QPS won't hit this. Held-out (lower-volume) p95 was **5.2s**.

## Limits / honest caveats

1. **48.5% TKB-sweep is not 70%.** Plan target was 70% with gpt-4o. We use gpt-4o-mini (deployed Azure). gpt-4o-mini at 50-tool function-calling is empirically 10-20pp weaker than gpt-4o per OpenAI's own benchmarks. Upgrade to gpt-4o would likely lift 48.5% → 60-70%; that's a Damir-deploy decision.
2. **The 40 `no_tool_call` errors** (4.2% on TKB sweep) are mostly `_multipatch` and other rare batch-update tools. The LLM is being conservative — these fall through to the L5 confidence gate's safe fallback. Better data on these tools (more anchors, better TKB intent) would close most of the gap.
3. **TKB-sweep queries are slightly synthetic** — they're regenerated from the same gpt-4o-mini Phase 1 ran. The held-out 67.2% is the more honest signal. It is a small set (58 queries) and is skewed toward driver `vehicle_info` queries (25/58 = 43%).
4. **Latency p95 11.5s** under bench load is unacceptable for WhatsApp UX. Two mitigations: (a) Azure quota uplift removes 429-retry backoffs; (b) Quick-Path catches ~40% of driver traffic at 0 LLM cost.
5. **Production not validated against real Damir users yet.** Smoke test (6 representative queries → 6/6 correct) + held-out 67.2% are the strongest evidence so far.

## What's next (deferred)

- **Production deploy**: V2_ENABLED=1 + Azure VM provisioning (Damir owns timing).
- **Quick-dial frequent-tools layer** (Phase 6 of the original plan): once we have production telemetry on the top 20-50 actually-used tools, build a regex-based fast path to skip the LLM call for them.
- **gpt-4o deployment**: if Damir can provision gpt-4o on `m1-ai-dev`, the router instantiation just needs an env-var flip (`AZURE_OPENAI_DEPLOYMENT_NAME`).
- **Iterating on the 40 no-tool-call errors**: the `_multipatch` tools could get better anchors + cardinality hints in TKB.
