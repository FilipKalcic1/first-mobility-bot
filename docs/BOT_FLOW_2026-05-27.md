# BOT FLOW — karta puta poruke (2026-05-27)

Točno trenutnom kodu (uklj. `tool_choice="required"` + echo prije mutacije). Grounded u `services/v2/engine.py` `_dispatch_message`.

## Pregled — 3 grane
Svaka poruka (nakon filtera) ide u JEDNU granu:
- **[A] Vozačke prečice** ("kolika km", "registracija") → instant iz cached snapshota. **Deterministički, READ, bez routinga.**
- **[B] Flow** (poznata višekoračna namjera: "rezerviraj" / "upiši km" / "prijavi kvar") → skripirani koraci → **hardkodiran tool**. **Deterministički, WRITE, bez routinga.**
- **[C] Opći put** (sve ostalo) → vođena selekcija: akcija → top-3 toolova → potvrda → izvrši. **Probabilistički — OVDJE živi routing (~nepouzdan).**

[A] i [B] su sigurne prečice koje NAMJERNO zaobilaze routing. [C] je generički put za 950 toolova.

## Puni redoslijed (dispatch)
```
poruka → process_message → _dispatch_message
 ├ L-1  rate-limit                        (odbij ako preko limita)
 ├ L0.5 PII-scrub                         (OIB/IBAN/telefon → [REDACTED])
 ├ L0.6 input-sanitizer                   (prompt-injection guard)
 ├ L0   identity.resolve(phone)           (tko si: person_id, tenant, vozilo)
 ├ PENDING nastavak? (odgovor na prošli turn)
 │    ├ pending_params   → "R-123"/"gorivo" = vrijednost koju smo tražili
 │    ├ pending_mutation → "Da/Ne" na confirm
 │    ├ pending_clarify  → "1/2/3" izbor kartice
 │    └ flow korak       → idući korak flowa
 ├ L0.7 crisis / L0.75 negacija / L0.8 multi-intent / L0.85 meta ("tko si ti")
 ├ L1   special (welcome / GDPR / handover)
 ├ L1.5 nepoznat broj → enrollment poruka
 ├ L2a  intent_type.classify → {pitanje-o-sebi | akcija | flow | drugo}

 └ [C] inače → vođena selekcija (cascade)
```

## [A] Vozačke prečice (driver-basics)
- Okida: `intent_type=question_about_self` + `is_known` + embedding-match ([engine.py:477](../services/v2/engine.py#L477)).
- Radi: vozilo/km/registracija su VEĆ u identity snapshotu (dohvaćeni na resolve) → formatter izvuče polje → odgovor. **0 API poziva, 0 routinga, 0 pickera.**
- Primjer: "kolika mi je km" → "Trenutna kilometraža: 145.000 km".

## [B] Flow (deterministički višekorak)
Okida: `intent_type=flow_request` + keyword ([engine.py:738](../services/v2/engine.py#L738) `_guess_flow_name`: rezerv/booking → booking; upis/unesi/stanje → mileage; prijav/kvar/štet → case). Tool je **hardkodiran** u flowu (bez routinga).

| Flow | Koraci | Tool |
|---|---|---|
| **booking** | pitaj period → **DOHVATI slobodna vozila** → izaberi → potvrdi → izvrši | `post_VehicleCalendar` |
| **mileage** | pitaj broj → potvrdi → izvrši | `post_AddMileage` |
| **case** | pitaj opis → potvrdi → izvrši | `post_AddCase` |

- Booking je jedini s pravim višekorakom (lookup→izbor) koji [C] ne može; mileage/case su jednostavni ali **deterministički** (zato prečice, ne "redundantni").
- Flow ima vlastiti ASK_CONFIRM + sad prolazi `_coerce_llm_params` prije izvršenja; **booking lookup (`get_AvailableVehicles`) je ožičen** (round-trip u [`_continue_flow`](../services/v2/engine.py#L764), shape provjeren uživo). Ne zove `decide_mutation`, ali gate je čisto-metodni (svaki write = confirm) a flow svejedno uvijek traži Da/Ne — nema sigurnosne razlike.

## [C] Opći put (vođena selekcija — "cascade")
Free-text → bot ne zna KOJI od 950 toolova → mora ga PRONAĆI. Zato 3 turna:
```
Turn 1: action picker → "Što želiš? 1 POGLEDATI 2 UNIJETI 3 IZMIJENITI 4 IZBRISATI"
        (spremi pending_clarify: original_query + stage=ACTION_GLOBAL)
   │ korisnik "2"
Turn 2: akcija → metode {POST}
        catalog_scoper.scope(tenant_id, methods, drop_internal) → kandidatski set
        anchor cosine top-50 (ada-002)                     ← retrieval (recall@50 ~91%)
        LLM (gpt-4o-mini, tool_choice="required") bira 1   ← pick
        hallucination-check (pick ∈ top-50)
        top-3 picker: LLM-pick = kartica #1, anchor #2-3   (recall@3 ~47% na hard setu)
        "Razumio (UNIJETI): 1 …  2 …  3 …"
   │ korisnik "1"
Turn 3: chosen tool → param-collection:
        _compute_missing_required → pitaj required koji fale (jedan po jedan)
        *TypeId resolver: "gorivo" → /Lookup → id 3 (ili pitaj s popisom)
        array/object required → pošteno odbij
   → _run_gate_and_execute (vidi Mutation safety)
```

## Mutation safety (zajednički gate — [C], i cilj za [B])
`_run_gate_and_execute` / `_finalize_after_params`:
1. `_coerce_llm_params` (12,5→12.5; 17.05.2026→ISO; whole-float→int)
2. `mutation_gate.decide_mutation` — **čisto po metodi, uniformno za svih 950** (Filip 2026-05-27): GET→auto; DELETE→"⚠️ TRAJNO BRISANJE"; ostali write→"Potvrđuješ?". Bez per-tool range/critical specijala — provjeru vrijednosti nosi echo.
3. **echo** `_render_param_echo` — potpun čitljiv prikaz unosa: prvo **cilj kao IME** ("• Vozilo: DA053F", nikad UUID), pa svaka user-vrijednost ("• Broj km: 50000", `*TypeId` kao "Gorivo"). Plumbing (person/tenant id, konstante) skriven. Field-labele humanizirane dok se ne generira `param_labels_hr.json`. (+ risky-warn ako tool nedovoljno opisan.)
4. spremi pending_mutation → korisnik "Da" → execute
5. executor: inject context (VehicleId iz identiteta) → completeness-guard (fali required context → odbij) → split po location (path/query/body) → API
6. formatter (LLMFormatter) → HR odgovor; na 4xx → ApiErrorTranslator

- **[B] flow** ne zove `decide_mutation` (ima vlastiti ASK_CONFIRM = ekvivalent: svaki write se potvrđuje), ali sad prolazi isti `_coerce_llm_params` + isti `parse_reply` (Da/Ne) kao [C]. Razlika je samo prikaz: [C] echo-lista, [B] čitljiva bespoke potvrda ("Upisat ću X km na vozilo Y") — namjerno (bez UUID-a).

## Iskreni caveati
- **Routing ([C]) je nepouzdan** na teškom long-tailu (recall@3 ~47%, p@1 ~32-37%, PUT/PATCH ~0%). Pravi driver-promet (km/registracija) ide [A]/[B] (deterministički) → pouzdaniji.
- **Enum/business validacija = nema** (0 enuma u M1 Swaggeru) → reaktivni 422→HR je mreža.
- **Nikad live** — nijedan mutacijski poziv nije pogodio pravi M1 (token zaključan). Smoke je prvi pravi test.
- **Labele u echu** su humanizirana imena ("Value") dok se ne generira `param_labels_hr.json`.
